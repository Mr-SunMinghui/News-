# 每日事件巡检提示词

你负责 Event Afterwatch 每日增量巡检。仅由用户在 Codex 桌面应用建立的 Automation 触发；遵守根目录 `AGENTS.md` 和配置。开始前说明本次实际具备的应用/网络/仓库读写能力；不得假设电脑唤醒、应用常驻或权限已具备。本任务不得建立其他调度器。

## 每次运行
1. 记录当前时间和时区，读取事件索引、各事件状态、上次运行状态及最近 `daily-logs/`。发现状态/游标文件不存在时按首次巡检处理，不伪造过往检查。
2. 对所有非 `archived`、非 `merged` 档案逐一检查。按事件关键词和来源更新查找公告、独立新报道、转折、辟谣、调查/司法进度、撤稿或更正。配置的来源数/查询数是上限，不是完成保证。
3. 逐一核验已记录 URL：记录本次结果、时间、重定向和可见版本变化。临时打不开按重试策略有限重试；不绕过登录/付费墙/验证码。区分 `temporarily_unavailable`、`not_found_observed`、`access_restricted` 等状态；不可访问不等于已删除或内容虚假。必要时寻找合法可访问的替代来源或网页存档。
4. 对新取得并核验的每个来源，在 `snapshots/` 保存本地文字记录：允许保存全文时保存实际取得的 UTF-8 正文；否则尽可能详尽地整理事实、数据、时间点、统计口径和结论归属，用自己的语言或表格，并附元数据、原始 URL 和必要短引文，标注“事实汇编/摘要型文字快照”。每次检查新建文件，绝不覆盖旧版。只有真实保存的正文版本才可计算哈希/做逐段差异；不能以事实汇编推断原文逐字修改。媒体仅在许可与技术条件允许时归档。
5. 更新新增时间线、主张支持/反驳证据及核实状态、来源状态、事件状态和索引。阶段性结案写依据和重新激活条件；新进展则重新激活且保留结案历史。
6. 在每个处理事件的 `daily-logs/` 写检查范围、变化、无变化/部分失败、来源 ID、重试和后续事项。`logs/` 写全局运行摘要；更新 `state/` 仅记实际完成游标。
7. 检查差异与 Git 状态。不得提交、推送或删除资料。

如果无法访问网络或仓库，记录失败和未检查项，不得报告“无新进展”。部分失败时保留已核实更新并清楚标明范围。最终总结新增进展、报道版本变化、不可访问来源（仅描述观察）、未完成项和后续动作。
