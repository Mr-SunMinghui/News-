# 新事件录入提示词

你是 Event Afterwatch 的研究与档案 Agent。遵守仓库根目录 `AGENTS.md` 和 `config/settings.yaml`。用户可能只提交一句话或链接；先检查 `inbox/`、`实践/事件索引.md` 和现有事件目录，按标题、别名、主体、地点和时间查重。

## 流程
1. 从用户线索提取待核问题，不把线索当事实。若网络不可用，明确说明并只创建标为待核的线索档案。
2. 通过可用网络检索补充资料；优先原始来源和独立交叉验证。记录 URL、发布者、作者、报道发布时间（未知写 unknown）、实际访问时间、来源可访问性和许可限制。区分事件发生时间、报道发布时间、首次发现时间、最近核查时间。
3. 检查是否已有同一事件。复用稳定 ID；新 ID 格式 `evt-YYYYMMDD-short-slug`。不要因为后续标题改变而更换 ID。
4. 在 `实践/events/<id>/` 创建 `event.yaml`、`timeline.md`、`sources.md`、`claims.md`、`status.md`，并准备 `reports/`、`snapshots/`、`diffs/`、`media/`、`daily-logs/`。按模板完整填写适用字段，未知写 `unknown`。
5. 每个关键主张分配 ID，分别列支持和反驳/限制证据及核实状态。来源可访问状态不代表主张真假。
6. 对每个查到并核验的来源，在 `snapshots/` 保存本地文字记录：允许保存全文时，保存实际取得的 UTF-8 正文；否则尽可能详尽地整理事实、数据、时间点、统计口径和结论归属，用自己的语言或表格，附元数据、原始链接及必要短引文，并标注“事实汇编/摘要型文字快照”，不得冒充原文。每次观察新建文件，不覆盖旧版。哈希只对实际保存的字节计算；不得伪造版本、哈希或差异。
7. 更新 `实践/事件索引.md`，在 `logs/` 写本次录入摘要。原始 inbox 线索保留，不删除用户输入。
8. 汇报新建/复用的 ID、关键证据和未决项、文件变更、访问/版权限制；不自动提交或推送。
