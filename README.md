# Event Afterwatch

长期、可追溯地观察互联网事件的进展，以及报道和来源本身的变化。人提供一句话或若干链接，Agent 补充调查、建立时间线和证据记录；后续由 Codex 桌面 Automation 按日触发巡检。

快速浏览入口：[打开项目速览网页](速览.html)。每个事件目录内也有独立的 `速览.html`，按时间线查看关键节点，并可跳转到证据、来源和状态档案。新增事件时从 `实践/templates/event/速览.html` 复制页面模板。

## 目录

```text
AGENTS.md                 项目长期规则
速览.html                 全部事件的本地网页入口
config/settings.yaml      默认监测参数（不含密钥）
inbox/                    待整理的一句话或链接
实践/README.md             档案约定
实践/事件索引.md           事件目录与状态概览
实践/events/               按事件 ID 分目录的档案
实践/templates/event/速览.html  新事件速览网页模板
prompts/                   新事件录入和每日巡检提示词
logs/                      每次运行的跨事件摘要
state/                     机器可读的运行游标/示例
```

## 使用方法
1. 将简短线索放到 `inbox/`，或在 Codex 任务中提交一句话/链接，并调用 `prompts/intake-event.md` 的流程。
2. Agent 检索独立来源，查重后创建事件档案，更新事件索引；未经核实的信息明确标为待核。
3. 在 Codex 桌面应用创建每日 Automation，将 `prompts/daily-monitor.md` 作为任务指令，并确认应用运行、设备唤醒、联网和工作区读写权限是否满足当前设置。
4. 每次运行检查日志、差异和 Git diff；本项目不自动提交或推送。

## 第一阶段范围与限制
本阶段仅初始化规则、目录、配置和提示词。尚未实现网页抓取器、自动哈希/段落差异工具、媒体下载器、重复事件算法、自动事实裁定、告警服务或自动创建 Automation。版本比对和媒体保存必须由 Agent 在实际取得材料且许可允许时执行；不可访问不等同于删除。定时任务是否能在应用关闭、设备休眠或离线时运行取决于桌面端实际能力，需实测，不作保证。

## 安全
遵守根目录 `AGENTS.md`。不在仓库保存凭证；不绕过付费墙、登录、验证码或版权/技术限制。仅在用户明确要求时执行 Git 提交或推送。
